# SSTP GUI

Нативный, самодостаточный SSTP VPN-клиент для macOS с современным
GUI на egui. Без `pppd`, без `sstpc`, без зависимостей от Homebrew — весь
стек протоколов SSTP + PPP (TLS, HTTP-рукопожатие, SSTP-фрейминг,
LCP/CHAP/IPCP-переговоры, ключи MPPE, SSTP crypto-bind) реализован с нуля
на Rust и компилируется прямо в один `.app` размером ~15МБ.

## Зачем

В macOS нет встроенной поддержки SSTP, а обычный обходной путь —
[`sstp-client`](https://github.com/eivnaes/sstp-client), управляющий древним,
неподдерживаемым `pppd` от Apple — на практике довольно хрупкий: `pppd`
ненадёжно снимает свой интерфейс и изменения маршрутов при завершении,
его логирование практически невидимо, а включение `defaultroute` для
реальной маршрутизации трафика через туннель может создать петлю
маршрутизации, убивающую управляющее соединение в момент её появления.
Этот проект заменяет всю эту цепочку зависимостей одним Rust-бинарником,
который сам владеет TLS-сессией, управляющим протоколом SSTP,
PPP-переговорами и сетевым интерфейсом macOS напрямую — нет внешнего
процесса, который может упасть, нет закрытой логики маршрутизации, с
которой приходится бороться.

## Требования

- macOS 11+
- Rust (stable, edition 2024)
- SSTP VPN-сервер (например, Windows RRAS или [accel-ppp](https://github.com/accel-ppp/accel-ppp))

## Сборка

```sh
./build.sh
```

Собирает release-бинарник, при необходимости генерирует иконку приложения
и собирает `SSTP GUI.app` (подписан ad-hoc) в корне репозитория. Можно
открыть его напрямую или перенести в `/Applications`.

## Архитектура

- **`sstp-proto/`** — движок протокола: TLS + HTTP-рукопожатие, бинарный
  SSTP-фрейминг, PPP (LCP/CHAP-MSCHAPv2/IPCP), вывод ключей MPPE,
  SSTP compound-MAC crypto-bind и `utun`-интерфейс macOS. Не имеет GUI-
  зависимостей, поэтому собирается и прогоняет ~70 unit-тестов за секунды.
  Почти каждая деталь формата данных на проводе сверена с RFC 1661/1332/
  1877/1994/2759/3079, а там, где RFC неоднозначны — с реально захваченными
  переговорами живого сервера.
- **`src/`** — GUI на egui, управление профилями/Keychain и
  рут-привилегированный воркер-процесс. Создание `utun`-интерфейса и смена
  маршрутов требуют root на всё время жизни соединения (а не разовой
  команды), поэтому тот же бинарник перезапускает сам себя как
  `sstp-gui --vpn-worker <server> <username>` через `osascript`
  (`do shell script ... with administrator privileges`) и координируется с
  непривилегированным GUI-процессом через небольшие файлы в
  `~/Library/Application Support/sstp-gui/` (у `do shell script` нет
  канала обратной связи в реальном времени к вызывающему процессу).

## О безопасности

Перед тем как направить маршрут по умолчанию на интерфейс туннеля,
воркер добавляет маршрут до IP самого VPN-сервера через исходный шлюз —
чтобы TLS-соединение самого туннеля не могло замкнуться само на себя.
Если воркер-процесс неожиданно завершается, GUI обнаруживает сломанный
маршрут по умолчанию и автоматически восстанавливает исходный шлюз.
